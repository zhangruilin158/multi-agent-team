# 多智能体框架总览（技能内置参考）

> 本文件汇总 5 类主流「多 Agent / 多智能体」开源能力，方便触发技能后快速选型与搭建团队。
> 配套源码已下载至工作区 `ai-agent-frameworks/` 目录（每个能力一个子文件夹）。若未下载，技能会引导用克隆工具获取。

## 一、调动词语（Trigger）

当你想基于本文件快速搭建一个多 Agent 系统时，使用以下任一词语触发：

- **「帮我新建一个多Agent团队」**
- **「多Agent团队」**
- **「多Agent」**

触发后，按下方「如何选型」与「安全须知」快速落地。

## 三、各能力类型功能与使用场景

### 1. 轻量多智能体引擎
- **功能**：把多个「角色化」Agent 组成团队，每个 Agent 有角色、目标、工具与记忆，通过任务流转互相配合完成复杂任务。主打轻量、不依赖第三方链路库。
- **使用场景**：需要多个 AI 分工的流水线，例如「调研 Agent + 写作 Agent + 审核 Agent」自动产出报告、自动做市场/竞品分析、内容生成工作流。
- **适合**：想快速搭一支「小团队」跑具体业务任务的用户。

### 2. 需求转软件框架
- **功能**：将 SOP（标准作业流程）编码进多智能体，模拟一家「AI 软件公司」——产品经理、架构师、工程师等角色协作，把一句话需求变成代码与文档。
- **使用场景**：需求→软件原型的快速生成、自动化软件工程、教学演示「AI 团队如何协作」。
- **适合**：想用「公司化分工」自动产出代码/文档的用户。

### 3. 研究型框架
- **功能**：最早的 LLM 多智能体框架之一，主打「角色扮演」式自主 Agent 协作，探索 Agent 的 Scaling Law，内置大量数据集、工具与模型接口。
- **使用场景**：多智能体学术研究、自动化数据生成、对话式协作系统实验。
- **适合**：研究者、想做多 Agent 实验与数据合成的用户。

### 4. 可编排代理框架
- **功能**：企业级多 Agent 编排框架，支持串行 / 并行 / 层级等多种 Agent 拓扑，强调生产可用与可组合。
- **使用场景**：大规模 Agent 编排、把多个 Agent 串成 pipeline 跑业务。⚠️ 依赖树庞大，安装时需重点审查。
- **适合**：需要复杂 Agent 拓扑（流程图式编排）的工程用户。

### 5. 带沙箱的工作台
- **功能**：「超级 Agent」工作台，能调研、写代码、生成内容，自带沙箱、记忆、工具、子 Agent、消息网关，是一整套应用（前端 + 后端），非纯库。
- **使用场景**：深度研究助手、自动化调研报告、端到端任务自动化。沙箱化执行，默认比其余框架更安全。
- **适合**：想要开箱即用的「研究 / 自动化工作台」、且重视执行隔离的用户。

## 四、如何选型（决策建议）

- 想**快速组小团队跑业务任务** → **轻量多智能体引擎**
- 想**一句话需求变软件/文档** → **需求转软件框架**
- 做**多 Agent 研究 / 数据合成** → **研究型框架**
- 需要**复杂拓扑编排（生产级 pipeline）** → **可编排代理框架**
- 想要**开箱即用的研究/自动化工作台 + 沙箱安全** → **带沙箱的工作台**

---

## 五、安全须知（务必先看）

1. **本地代码执行风险**：多数代码框架默认在本机直接运行 LLM 生成的代码或命令，存在被诱导执行危险操作的可能；**带沙箱的工作台用沙箱隔离，相对更安全**。
2. **API Key 与费用**：全部需要 LLM API Key，会真实扣费；输入内容会发往对应服务商。
3. **数据外发**：prompt、上下文、喂入的文件会传给第三方大模型，**切勿放入密钥或隐私数据**。
4. **供应链 / 依赖**：`pip install` 会拉大量依赖；**可编排代理框架依赖树异常庞大且历史上有争议**，务必装在独立虚拟环境并审查。
5. **遥测**：部分框架默认上报匿名使用统计（一般可关闭）。
6. **已知漏洞**：截至整理时，各仓库在代码托管平台上**均无公开 Security Advisory**，来源可信（宽松开源许可、高星标、近期活跃）。

> 落地建议：装在独立虚拟环境 → 不喂敏感数据 → 先小任务试跑 → 对可编排代理框架重点审查依赖。

## 六、汇总到通用角色库（统一角色库）与补齐

把所有识别到的库，按 **通用角色库的「部门 / 角色」模型** 统一归并。

### 6.1 各库的「Agent 形态」分两类
- **A. 角色 / 人设包（Persona）**：通用角色库（英文）、中文角色库。成百上千个"专家"角色定义，按部门（engineering / research / marketing / finance / design / security / product / sales / support / testing / healthcare / specialized …）组织，直接塞进主流 AI 编码工具即插即用。
- **B. 代码框架 / 运行时（Engine）**：前述 5 类能力 + 一键编排器 + 国产 Python 框架。它们是 SDK / 应用，用代码定义 Agent 并负责编排与执行。

### 6.2 通用角色库已覆盖的「Agent 原型」（其他框架演示的角色）
| 其他框架示例角色 | 通用角色库对应覆盖 |
|------|------|
| 需求转软件框架：产品经理 / 架构师 / 工程师 / 测试(QA) / 项目经理 | product、engineering(architect/engineer)、testing、project-management 部门均有对应人设 |
| 轻量多智能体引擎：自定义角色 Agent | 通用，任意角色都可映射到某部门人设 |
| 研究型框架：角色扮演 Agent | 通用 |
| 可编排代理框架：worker / orchestrator | engineering-multi-agent-systems-architect |
| 带沙箱的工作台：researcher / coder / supervisor | research + engineering + project-management |
| 国产 Python 框架：领域专家 Agent | 各领域部门均有专家人设 |

**结论：在「Agent 角色 / 人设」层面，通用角色库已覆盖上述所有框架演示的原型**——它本身就是几百个角色的总库，比各框架自带的示例角色更全。

### 6.3 唯一的真实缺口：中国市场专属 Agent
英文通用角色库缺**中国本地化场景**角色，只存在于中文角色库：
- 小红书 / 抖音 / 微信 / 飞书 / 钉钉运营专家
- Qt 上位机 / 机械设计等本土工程角色
→ 这正是「补齐通用角色库没有的 Agent」的部分，由中文角色库补上。

### 6.4 下载决策
- ✅ **已下**：通用角色库（英文总库，覆盖通用角色）+ 中文角色库（补齐中国市场份额色）。
- ⏭️ **不再单独下**：一键编排器、国产 Python 框架——它们是"运行时 / 引擎"，不是角色缺口；实际的编排与执行引擎已由最初的 5 类代码能力覆盖。
- 📌 关键区别：通用角色库是"角色库"，不是"运行引擎"。真要跑起多 Agent 协作，仍需代码框架或编排器作引擎；角色库负责提供"有哪些专家可用"。

## 七、可运行的多 Agent 团队 Demo（技能内置脚手架）

技能内置可直接运行的 demo，位于 `../assets/multi-agent-team-demo/`：

- **引擎**：轻量多智能体引擎；**角色素材**：通用角色库。
- **核心特点**：团队组成**完全可配置**——`team_config.py` 的 `TEAM` 列表想加几个 Agent 就加几个，**不限于"研究员 + 工程师 + 审核"三个**。项目需要"产品经理""安全专家""技术作家"等，直接增删；人设可从 `通用角色库/<部门>/<角色>.md` 取。
- **文件**：`team_config.py`（唯一要改的配置）、`build_team.py`（组建并运行）、`requirements.txt`、`.env.example`、`README.md`。
- **运行**：`build_team.py --dry-run` 预览团队（不花钱、不调模型）；配置 `.env` 密钥后 `build_team.py --topic "主题"` 真实运行。
- **触发**：说「多Agent」「多Agent团队」「帮我新建一个多Agent团队」即可触发 **多智能体团队搭建** 技能自动搭建。
- **验证**：已用轻量多智能体引擎跑通 `--dry-run`（组建团队并打印角色，未调用大模型、零费用）。
