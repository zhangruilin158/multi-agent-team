## ① 端到端主流程

```mermaid
flowchart TD
  A["触发「多Agent团队」"] --> B["判定需求形态（内部）"]
  B --> C["组建领域小组<br/>每领域 ≥2 人 · 从全量清单招募"]
```

## ③ 组队铁律：先查池、后新建

```mermaid
flowchart TD
  S["查统一角色池<br/>335 个唯一角色 / 23 个领域"] --> Q{"池内有匹配角色？"}
  Q -- 是 --> R["复用其人设<br/>不重写 role / goal / backstory"]

  R --> W["写入 TEAM<br/>带 domain + source"]
  N --> W
  W --> V["校验：每领域 ≥2 人"]
  V --> D["dry-run 验证组队 → 真实运行"]
```

## ④ 两类讨论与收敛（核心规则）

```mermaid
flowchart TD
  G["领域小组<br/>每领域 ≥2 人"] --> G1["小组讨论 · 聚焦方案本身<br/>充分比较各 agent 的思路"]
  G1 --> G2["每领域只出 1 条建议<br/>选定哪个方案 + 关键理由"]
  G2 --> T1["团队讨论 · 聚焦如何融入任务<br/>衔接 · 职责划分 · 执行顺序"]
  T1 --> T2["产出：如何实施该方案<br/>解决跨域冲突，收敛唯一方案"]
  T2 --> F["落地执行 / 给出具体示例"]
```

**两类讨论的分工**：

| | 小组讨论（领域小组内部） | 团队讨论（跨领域全团队） |
|---|---|---|
| 焦点 | 方案本身 | 方案如何融入当前任务 |
| 产出 | 选哪个方案 + 理由 | 如何实施该方案 |

**沟通约束**：全程极度精简，只给结论 + 关键理由（仅约束讨论过程，不约束最终交付物）。

## ⑥ 角色资源：双视图

```mermaid
flowchart LR
  R["agent-role-libraries<br/>583 角色 + 25 工作流技能"] --> V1["统一角色池<br/>去重 335 个 → 组队用"]
  R --> V2["agent 全量清单<br/>不去重 608 条 → 讨论用"]
```

> 为什么讨论要用不去重的？小组讨论的价值在于**比较不同 agent 的思路差异**——同名同职责但来自不同库的 agent，给出的方案可能不同，所以重复的也要进组。

## ⑦ 安全须知（每次落地必提示）

```mermaid
flowchart TD
  A["每次落地"] --> S1["本地代码执行风险<br/>优先沙箱"]
  A --> S2["角色包权限<br/>同等文件/命令权限，先 Review"]
  A --> S3["密钥管理<br/>只在 .env，绝不硬编码"]
  A --> S4["数据外发<br/>勿喂密钥或隐私数据"]
  A --> S5["费用<br/>按 token 计费，先用便宜模型试跑"]
```
