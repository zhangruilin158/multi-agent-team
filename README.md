# 技能包：多智能体团队搭建（multi-agent-team）

一句话：**你说一句"帮我组个多 Agent 团队"，它就去你下载好的角色库里挑合适的 AI 专家拼成团队，库里没有的才现造，最后直接给你一个能跑的团队。**

---

## 这包是干嘛的（大白话）

你不用再纠结"该用哪个多智能体框架"。这个技能把市面上主流的多 Agent 框架和几百个现成 AI 角色（专家人设）整理好了，**你只管说要做什么，它来选型、组队、落地**。

具体能帮你三件事：

1. **选型不纠结（选完直接用）** —— 你说"想组个小团队跑业务""想一句话变出软件""想做研究"，它对照内置决策表**直接替你定好用哪个框架，并马上动手搭起来**——不跟你讨论"该用哪个"，选完就用，给你能跑的东西。
2. **组队不手写** —— 触发"新建一个多Agent团队"后，它先到你下载好的角色库（通用角色库，几百个专家：产品经理、工程师、审核、安全专家……）里找现成角色，直接复用；库里真没有的才新建。团队要几个角色就几个，不限于固定的三个。
3. **落地可运行** —— 自带一个轻量多智能体引擎脚手架，改一个 `TEAM` 配置就能跑。先用 `--dry-run` 免费预览团队，配好密钥再真实运行，零试错成本。

## 你为什么需要它（能给你什么帮助）

- **省时间**：不用自己读多个框架的文档、比来比去。
- **不重复造轮子**：几百个专家人设已经有人写好了，直接拿，不用每次从头写 Agent 的"人设"。
- **安全兜底**：每次落地都提醒本地代码执行风险、API 费用、数据外发、密钥管理；带沙箱的工作台还带沙箱。
- **可扩展**：今天要"研究员+工程师+审核"，明天要"产品经理+安全专家+技术作家"，改个列表就行。

## 默认引擎说明（大白话）
脚手架的**默认引擎是「轻量多智能体引擎」**（底层即你保留的 crewai，去品牌后内部命名为 `lightweight`），开箱即用，无需自己选型。
- **可插拔**：除默认 `lightweight`，另内置**零依赖的 `mock` 引擎**——不装任何第三方库也能跑完整流程（`--engine mock`），或先 `--dry-run` 免费预览（连 mock 都不需要）。
- **换引擎**：改 `team_config.py` 的 `ENGINE` / 命令行 `--engine` / 环境变量 `TEAM_ENGINE` 任选其一；新增引擎只需在 `engines/` 写一个适配器类并登记，主流程不动。

> 三种形态速览：①搬现成专家（角色库即插即用）②代码里自己组队（SDK / 轻量引擎脚手架）③开箱应用 / 企业级框架。形态一是"专家池"，形态二/三是"引擎"，可组合——角色库人设可直接喂给代码引擎或应用。详见 `UPLOAD.md`。

## 运行流程图
技能从触发到交付的完整链路见 `references/团队搭建流程.svg`：
**用户说「多Agent团队」→ 内部判定需求形态（四类分支）→ 内部选型（不对外纠结）→ 组队铁律（先查通用角色库复用、库无才新建）→ 落地脚手架（dry-run 预览 → 配密钥 → 真实运行）→ 交付与安全提示。**

## 怎么装（迁移 / 分享）

把整个 `multi-agent-team/` 文件夹复制到目标机器的技能目录即可：

- 用户级：`~/.workbuddy-ai/skills/multi-agent-team/`
- 项目级：`<项目>/.workbuddy-ai/skills/multi-agent-team/`

放置后，在 WorkBuddy 里说「多Agent」「多Agent团队」「帮我新建一个多Agent团队」即可触发。

## 怎么用（最快路径）

```bash
# 1. 进脚手架目录，建虚拟环境并装依赖
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt      # Windows
# .venv/bin/pip install -r requirements.txt        # macOS/Linux

# 2. 先免费预览团队（不调用大模型、不花钱）
.venv\Scripts\python build_team.py --dry-run

# 3. 配密钥后真实运行
copy .env.example .env     # 编辑 .env 填入 API Key（或兼容服务商）
.venv\Scripts\python build_team.py --topic "你的主题"
```

想加角色？打开 `team_config.py`，往 `TEAM` 里复制一个字典改 `role/goal/backstory` 即可；
人设可直接从 `ai-agent-frameworks/通用角色库/<部门>/<角色>.md` 搬。

## 组队铁律（触发"新建团队"时强制）

库是 Agent 池，**先复用、后新建**：
1. 先查通用角色库 / 中文角色库有无匹配角色；
2. 有就直接引用其 `.md` 人设（role/goal/backstory），不重写；
3. 库里真没有的特有业务角色，才新建，并保持同一人设结构；
4. 最终团队落到 `team_config.py` 的 `TEAM`，先 `--dry-run` 验证再真实运行。

## 安全提醒（务必看）

- 默认本机让 LLM 生成内容（不执行代码）；若接会跑代码的 Agent，请上沙箱（如带沙箱的工作台）。
- 密钥只在 `.env`，绝不硬编码或提交。
- 输入会发往你配置的大模型服务商，**别喂密钥或隐私数据**。
- 真实运行按 token 计费，先用便宜的入门模型试跑。
